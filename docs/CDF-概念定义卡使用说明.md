# CDF 概念定义卡使用说明

## 功能概述

基于 RemNote 的 CDF（概念-描述符框架）理念，实现了概念定义卡功能。

## 核心特性

1. **双向卡片**：自动生成正向和反向两张卡片
   - 正向：概念 → 定义
   - 反向：定义 → 概念

2. **文档块引用**：概念必须是文档块的块引用

3. **支持挖空**：定义中可以包含挖空标记，每个挖空生成双向卡片

4. **专用渲染**：使用概念卡专用渲染器，视觉效果更好

5. **🆕 自动创建概念卡**：为引用的概念文档块自动创建概念卡
   - 如果概念文档块还不是卡片，会自动创建 Xiuyuan 概念卡
   - 卡片类型标记为 `concept`
   - 使用 `builtin-concept-simple` 模板

## 使用方法

### 基础语法

```
[[概念]]::定义
```

- `[[概念]]`：必须是文档块的块引用（在思源中输入 `((` 搜索文档）
- `::`：分隔符（也支持中文 `：：`）
- `定义`：概念的定义内容

### 示例 1：基础概念定义

```
((20240101010101-abc1234))::RemNote 独创的知识组织方法，将知识拆解为概念和描述符
```

假设 `((20240101010101-abc1234))` 引用的文档名为 "CDF"，则会生成：

**概念定义卡（2张）**：

**正向卡片**：
- 问题：CDF 的定义？
- 答案：RemNote 独创的知识组织方法，将知识拆解为概念和描述符

**反向卡片**：
- 问题：以下是哪个概念的定义？RemNote 独创的知识组织方法，将知识拆解为概念和描述符
- 答案：CDF

**🆕 概念卡（1张）**：
- 自动为 "CDF" 文档块创建概念卡
- 问题：CDF
- 答案：CDF（概念本身）
- 提示：✅ 已为概念「CDF」创建概念卡

### 示例 2：带挖空的概念定义

```
((20240101010101-abc1234))::RemNote 独创的知识组织方法，将知识拆解为==概念==和==描述符==
```

会生成 5 张卡片（4张概念定义卡 + 1张概念卡）：

**概念定义卡（4张）**：
1. 正向-挖空1：CDF 的定义？→ RemNote 独创的知识组织方法，将知识拆解为[___]和描述符
2. 反向-挖空1：以下是哪个概念的定义？RemNote 独创的知识组织方法，将知识拆解为[___]和描述符 → CDF
3. 正向-挖空2：CDF 的定义？→ RemNote 独创的知识组织方法，将知识拆解为概念和[___]
4. 反向-挖空2：以下是哪个概念的定义？RemNote 独创的知识组织方法，将知识拆解为概念和[___] → CDF

**🆕 概念卡（1张）**：
- 自动为 "CDF" 文档块创建概念卡

## 制卡方式

### 方式 1：符号监听制卡（推荐）

1. 在任意块中输入 `[[概念]]::定义`
2. 输入完成后，系统自动检测并创建卡片
3. 提示：✅ 已创建 2 张概念定义卡片（双向）

### 方式 2：块菜单模板制卡

1. 创建两个块：
   - 第一个块：文档块（概念）
   - 第二个块：包含 `::` 的定义块
2. 选中这两个块
3. 右键菜单 → 制卡 → 选择"概念定义"模板
4. 生成双向卡片

## 注意事项

### ✅ 正确示例

```
((20240101010101-abc1234))::这是一个定义
```

- 使用文档块引用
- 引用格式正确
- 有明确的定义内容

### ❌ 错误示例

**错误 1：不是文档块引用**
```
((20240101010101-abc1234))::定义
```
如果 `((20240101010101-abc1234))` 引用的是普通段落块而非文档块，会提示错误。

**错误 2：不是块引用格式**
```
CDF::这是一个定义
```
直接使用文本而非块引用，会提示格式错误。

**错误 3：缺少定义**
```
((20240101010101-abc1234))::
```
定义内容为空，无法创建卡片。

## 与 RemNote CDF 的对应关系

| RemNote | 思源插件 | 说明 |
|---------|---------|------|
| `Concept :: Definition` | `[[概念]]::定义` | 概念必须是文档块引用 |
| 双向卡片（默认） | 双向卡片（默认） | 自动生成正向+反向 |
| 概念用粗体 | 概念高亮显示 | 视觉上突出概念 |
| 支持挖空 | 支持 `==挖空==` | 每个挖空生成双向卡片 |

## 技术实现

### 模板定义

```typescript
{
  id: 'builtin-concept-definition',
  name: '概念定义',
  description: 'CDF 概念定义卡：[[概念]]::定义。生成双向卡片',
  cardRules: [
    {
      typeMarker: 'concept-definition-forward',
      frontFields: ['concept'],
      backFields: ['definition'],
    },
    {
      typeMarker: 'concept-definition-reverse',
      frontFields: ['definition'],
      backFields: ['concept'],
    },
  ],
}
```

### 卡片类型标记

- `concept-definition-forward`：正向卡片
- `concept-definition-reverse`：反向卡片
- `concept-definition-cloze-{index}-forward`：带挖空的正向卡片
- `concept-definition-cloze-{index}-reverse`：带挖空的反向卡片

## 最佳实践

### 1. 概念命名

- 使用清晰、简洁的文档名作为概念
- 避免过长的概念名称
- 使用标准术语

### 2. 定义编写

- 定义应简洁明了
- 一个概念一个定义块
- 可以使用挖空突出关键信息

### 3. 组织结构

```
📁 知识库
  📄 CDF（文档）
    📝 ((CDF))::RemNote 独创的知识组织方法...
    📝 ((CDF))::将知识拆解为==概念==和==描述符==
  📄 概念（文档）
    📝 ((概念))::CDF 中表示具体或抽象事物的元素
  📄 描述符（文档）
    📝 ((描述符))::CDF 中表示概念属性的元素
```

### 4. 与其他卡片类型配合

- 概念定义卡：定义核心概念
- 描述符卡（`;;`）：描述概念的属性
- 基础卡（`>>`）：问答式知识点
- 填空卡（`==`）：记忆关键细节

## 常见问题

### Q1：为什么必须使用文档块引用？

A：遵循 RemNote CDF 的设计理念，概念应该是独立的、可复用的实体。文档块在思源中最接近这个概念，且便于跳转和管理。

### Q2：可以在一个块中创建多个概念定义吗？

A：不建议。每个块应该只包含一个 `::` 符号，对应一个概念定义。

### Q3：反向卡片有什么用？

A：反向卡片帮助你从定义反推概念，加深理解和记忆。这是 RemNote CDF 的核心特性之一。

### Q4：挖空和双向卡片可以同时使用吗？

A：可以！每个挖空都会生成正向和反向两张卡片，实现最大化的学习效果。
