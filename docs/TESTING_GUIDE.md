# 测试指南

## 测试概览

本项目包含三个层次的测试：

1. **单元测试** - 测试单个函数/方法
2. **集成测试** - 测试组件配合
3. **端到端测试** - 测试完整用户流程

## 测试文件结构

```
src/
├── core/
│   ├── scheduler/
│   │   └── __tests__/
│   │       └── SchedulerRouter.test.ts          # 单元测试
│   └── queue/
│       └── __tests__/
│           └── e2e.queue.test.ts                # 端到端测试
└── ui/
    └── review/
        └── __tests__/
            └── e2e.review-ui.test.ts            # UI 端到端测试
```

## 运行测试

```bash
# 运行所有测试（监听模式）
npm test

# 运行所有测试（单次运行）
npm run test:run

# 运行测试并生成覆盖率报告
npm run test:coverage

# 使用 UI 界面运行测试
npm run test:ui

# 运行旧版自定义测试脚本
npm run test:legacy

# 运行单元测试
npm test -- --grep "单元测试"

# 运行端到端测试
npm test -- --grep "E2E"

# 运行特定文件的测试
npm test -- e2e.queue.test.ts
```

## 测试最佳实践

### 1. 单元测试
- 测试单个函数/方法
- 使用 Mock 隔离依赖
- 快速执行（毫秒级）
- 精确定位问题

### 2. 集成测试
- 测试组件配合
- 最小化 Mock
- 验证接口正确性
- 发现集成问题

### 3. 端到端测试
- 测试完整用户流程
- 真实环境（尽可能）
- 验证业务逻辑
- 发现系统级问题

## 添加新测试

### 添加单元测试

1. 在对应模块的 `__tests__` 目录创建测试文件
2. 使用 `describe` 和 `it` 组织测试
3. 使用 `expect` 断言结果

```typescript
describe('MyModule', () => {
  it('should do something', () => {
    const result = myFunction();
    expect(result).toBe(expected);
  });
});
```

### 添加端到端测试

1. 在 `__tests__` 目录创建 `e2e.*.test.ts` 文件
2. 使用 `describe('E2E: ...', ...)` 标记
3. 测试完整的用户流程

```typescript
describe('E2E: 用户复习流程', () => {
  it('应该完成完整的复习', async () => {
    // 1. 准备数据
    // 2. 执行操作
    // 3. 验证结果
  });
});
```

## 常见问题

### Q: 测试运行很慢怎么办？
A: 
1. 使用 `--grep` 只运行需要的测试
2. 检查是否有不必要的 `await`
3. 使用 Mock 替代真实 API 调用

### Q: 测试不稳定（有时通过有时失败）？
A:
1. 检查是否有时间相关的逻辑
2. 使用固定的时间戳而不是 `Date.now()`
3. 确保测试之间相互独立

### Q: 如何测试异步代码？
A:
1. 使用 `async/await`
2. 确保所有 Promise 都被 `await`
3. 使用 `vi.fn().mockResolvedValue()` Mock 异步函数
