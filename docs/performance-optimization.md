# SRS Browser 性能优化总结

## 优化目标
针对 SRS Browser 的性能问题进行了系统性优化，主要解决了：
- 数据加载缓慢（多次 SQL 查询）
- 缺乏缓存机制
- 筛选性能不佳
- 用户体验响应慢

## 优化措施

### 1. SQL 查询合并优化
- **问题**: 原来需要 4 次独立的 SQL 查询获取卡片信息
- **优化**: 合并为 1-2 次查询，使用 `Promise.all()` 并行执行
- **效果**: 减少 75% 的数据库往返时间

### 2. 内存缓存层实现
- **实现**: `CardCacheManager` 类
- **特性**: 
  - TTL 过期机制 (60秒)
  - 防止并发加载
  - 增量更新支持
  - 缓存统计功能
- **效果**: 首次加载后，后续访问几乎瞬时完成

### 3. 数据加载优化
- **pageSize**: 从 100 增加到 500，减少网络请求次数
- **批量处理**: 按 500 个 ID 分批处理，避免 SQL 过长
- **预加载**: 优化 `loadQueueCards` 使用缓存快速查找

### 4. 筛选性能优化
- **内存筛选**: `applyPresetFilter` 使用 switch 语句优化
- **早期返回**: 避免不必要的遍历
- **组合查询**: 将复杂筛选条件合并处理

### 5. 性能监控
- **工具**: `PerformanceMonitor` 类
- **监控点**: 
  - `loadCards`: 加载卡片列表
  - `loadAllCardsRaw`: 原始数据加载
  - `fetchRows`: 数据源获取
  - `fetchRowsFocus`: 聚焦数据获取

### 6. UI 增强
- **缓存状态**: 控制台显示缓存命中情况
- **强制刷新**: 清除缓存按钮
- **性能报告**: 一键输出性能统计

## 性能提升预估

| 卡片数量 | 优化前加载时间 | 优化后加载时间 | 提升倍数 |
|----------|----------------|----------------|----------|
| 100      | ~200ms         | ~50ms          | 4x       |
| 500      | ~500ms         | ~100ms         | 5x       |
| 1000     | ~1s            | ~150ms         | 6.7x     |
| 5000     | ~3-5s          | ~400ms         | 8x+      |

## 增量更新支持

批量操作会自动更新缓存：
- `batchReset`: 清除缓存
- `batchSuspend`: 增量更新卡片状态
- `batchSetPriority`: 增量更新优先级
- `batchDelete`: 从缓存中移除卡片

## 使用建议

1. **正常浏览**: 使用标准刷新按钮，享受缓存加速
2. **数据异常**: 使用强制刷新按钮，清除缓存重新加载
3. **性能分析**: 使用性能报告按钮，查看实时统计
4. **大数据量**: 优化效果更明显，特别是筛选和排序操作
