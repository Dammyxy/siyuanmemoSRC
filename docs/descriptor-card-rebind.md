# 描述符卡片重新绑定概念功能

## 功能概述

为描述符卡片添加了重新绑定概念的功能，允许用户在描述符块被移动到新的概念下时，自动更新卡片的概念引用。

## 使用场景

当你有一个描述符卡片（例如 `属性 ;; 值`），并且你将这个描述符块移动到了一个新的概念标题下，你可以使用重新绑定功能来更新卡片的概念引用。

### 示例

**原始结构：**
```
# 旧概念
属性1 ;; 描述1
```

**移动后：**
```
# 新概念
属性1 ;; 描述1
```

此时，描述符卡片仍然引用"旧概念"，你需要重新绑定到"新概念"。

## 使用方法

### 方法 1：在复习界面中重新绑定

1. 在复习界面遇到描述符卡片时
2. 点击底部的 "🔄 重新绑定概念" 按钮
3. 系统会自动向上探路查找新的概念块（标题块或文档块）
4. 如果新概念块还没有概念卡，系统会自动创建
5. 更新描述符卡片的概念引用

### 方法 2：在块菜单中重新绑定

1. 右键点击描述符块（包含 `;;` 的块）
2. 在 "SiyuanMemo" 子菜单中找到 "🔄 重新绑定概念" 选项
3. 点击后系统会自动执行重新绑定操作

## 技术实现

### 向上探路逻辑

重新绑定功能使用了正确的向上探路逻辑，与 `AutoCardHandler` 中的实现一致：

**探路规则**：

1. **在列表项块内的时候**：
   - 向上探路（最多 4 层）
   - 检查父块内容是否包含块引用 `((id))`
   - **块引用必须指向文档块** (type='d')
   - 如果文档块已经是概念卡，就绑定这个概念卡
   - 如果文档块还不是概念卡，会自动制作为概念卡并绑定
   - **绑定的是文档块本身，而非块引用**

2. **在非列表项块内的时候**：
   - 向上探路找最近的标题块 (type='h') 作为概念卡
   - 如果没有标题块，则使用所在文档块 (type='d') 作为概念卡
   - 如果标题块或文档块还不是概念卡，会自动制作为概念卡

**概念类型**：
- `block-ref`: 父块包含概念卡的块引用（列表项情况）
- `heading`: 标题块作为概念（非列表项情况）
- `document`: 文档块作为概念（非列表项且无标题块情况）

**为什么区分列表项和非列表项？**

这是基于 RemNote CDF 的设计理念：

**列表项情况**（使用块引用指向文档块）：
```
- ((20240101010101-abc1234))  # 引用到"Cell"文档块
  - 属性1 ;; 描述1
  - 属性2 ;; 描述2
```
在这种情况下：
- 块引用 `((20240101010101-abc1234))` 必须指向一个文档块
- 如果该文档块还不是概念卡，会自动制作为概念卡
- 描述符卡绑定的是文档块 `20240101010101-abc1234`，而不是包含块引用的列表项

**非列表项情况**（使用标题块）：
```
# Cell 概念

属性1 ;; 描述1
属性2 ;; 描述2
```

### 自动创建概念卡

如果找到的概念块还没有概念卡，系统会自动创建：

- 使用 `builtin-concept-simple` 模板
- 卡片类型标记为 `concept`
- 添加到默认牌组

### 更新字段映射

重新绑定会更新 Xiuyuan 实体的 `meta.fieldMapping.concept` 字段，指向新的概念块 ID。

## 注意事项

1. 只有描述符卡片才会显示重新绑定选项
2. 重新绑定会保持描述符块的 xiuyuan-id 不变
3. 如果向上探路找不到概念块，操作会失败
4. 重新绑定后，复习界面会自动刷新显示新的概念信息
