# 项目功能精简与模块扫描计划

## 项目现状分析

### 当前功能范围
- **核心功能**: FSRS 算法驱动的间隔重复系统
- **队列系统**: 神经漫游、刻意练习、筛选练习等多种队列
- **卡片浏览器**: 完整的卡片管理和筛选功能
- **原生适配**: 与思源原生 UI 的集成

### 功能复杂度评估
- **高复杂度**: 神经漫游系统（图遍历算法）
- **中复杂度**: 队列管理系统
- **低复杂度**: 基础闪卡功能

## 模块扫描结果

### 核心模块 (必需)
1. **FSRS 调度器** (`src/core/scheduler/`)
   - `SimpleFSRSScheduler`: 核心算法实现
   - `types.ts`: 调度器类型定义

2. **基础队列抽象** (`src/core/queue/abstraction/`)
   - `IQueueStrategy`: 队列策略接口
   - `Command.ts`: 命令模式实现

3. **数据访问层** (`src/core/siyuan/`)
   - `api.ts`: 思源 API 封装
   - `block.ts`: 块操作工具

### 扩展模块 (可选)
1. **高级队列** (`src/core/queue/strategies/`)
   - `NeuralRoamQueue`: 神经漫游（复杂度高）
   - `FinalDrillQueue`: 刻意练习
   - `FilterGroupQueue`: 筛选练习

2. **卡片浏览器** (`src/ui/browser/`)
   - `SRSBrowser.vue`: 完整浏览器界面
   - `browserService.ts`: 浏览器数据服务

### 辅助模块 (优化)
1. **性能优化工具** (`src/utils/performance.ts`)
2. **缓存管理层** (集成在 `browserService.ts`)

## 功能精简策略

### 第一阶段：保留核心
- 保留 FSRS 调度器
- 保留基础队列接口
- 保留数据访问层
- 保留原生 UI 适配

### 第二阶段：简化扩展
- 评估神经漫游队列的必要性
- 简化卡片浏览器功能
- 保留最常用的筛选和操作功能

### 第三阶段：优化性能
- 保持现有缓存优化
- 简化复杂查询
- 优化大数据量处理

## 模块依赖分析

### 核心依赖链
```
FSRS调度器 <- 队列策略 <- 数据访问 <- 思源API
```

### 扩展依赖链
```
神经漫游 <- 图遍历引擎 <- 权重计算 <- 查询引擎
```

## 精简实施计划

### 步骤1: 识别可选功能
- [x] 神经漫游队列（高复杂度，使用率待验证）
- [x] 高级筛选功能（卡片浏览器部分）
- [x] 复杂的队列重组功能

### 步骤2: 评估影响
- **用户影响**: 确保核心闪卡功能不受影响
- **性能影响**: 保持或提升性能
- **维护影响**: 减少代码复杂度

### 步骤3: 逐步精简
1. 标记可选功能为实验性
2. 提供精简版本选项
3. 逐步移除低使用率功能

## 风险评估

### 低风险项
- 简化高级筛选功能
- 优化大数据量处理
- 移除冗余UI组件

### 中风险项
- 移除神经漫游队列（可能影响特定用户）
- 简化队列管理系统（需确保兼容性）

### 高风险项
- 修改核心FSRS算法
- 改变数据存储结构
- 影响与思源的集成

通过系统性的模块扫描和功能分析，可以在保持核心闪卡功能的前提下，合理地精简项目复杂度。重点应放在移除低使用率的高级功能，同时保持和优化核心用户体验。
