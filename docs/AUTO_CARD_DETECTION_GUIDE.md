# 自动卡片检测功能使用指南

## 功能简介

自动卡片检测功能可以在你创建或编辑块时，自动识别卡片类型（Topic/Item）并标记，无需手动操作。

## 启用方法

1. 打开插件设置（右键点击顶栏 FSRS 图标 → 设置）
2. 切换到"增量阅读"选项卡
3. 找到"自动制卡（实时监听）"选项
4. 勾选启用
5. 点击"保存"按钮

## 工作原理

### 监听机制

- 监听思源的块创建和编辑事件
- 使用 2 秒防抖，避免频繁触发
- 自动检测卡片类型并标记

### 检测规则

**Item（卡片）**：
- 包含标记语法 `==答案==`
- 包含分隔符 `问题::答案`
- 标题块
- 列表项有列表子级（父子问答结构）
- 超级块有任何子级

**Topic（主题）**：
- 不符合以上任何条件的块
- 纯阅读材料

### 自动操作

1. **添加到 Riff Deck**：自动添加到思源原生闪卡系统
2. **标记 FSRS 属性**：添加 `custom-fsrs-card-id` 等属性
3. **标记卡片类型**：添加 `custom-fsrs-card-type` 属性（`topic` 或 `item`）
4. **初始化 A-Factor**：Topic 卡片自动初始化 A-Factor（从优先级推导）

## 使用示例

### 示例 1：创建 Item 卡片

```markdown
【 item 什么是 FSRS？::Free Spaced Repetition Scheduler ==间隔重复算法==】
```

**自动操作**：
- 2 秒后自动检测
- 识别为 Item（包含 `::` 和 `==...==`）
- 添加到 Riff Deck
- 标记 `custom-fsrs-card-type: item`

### 示例 2：创建 Topic 卡片

```markdown
【 topic FSRS 是一种基于记忆曲线的间隔重复算法，用于优化学习效率。】
```

**自动操作**：
- 2 秒后自动检测
- 识别为 Topic（纯阅读材料）
- 添加到 Riff Deck
- 标记 `custom-fsrs-card-type: topic`
- 初始化 `custom-fsrs-a-factor: 3.6`（假设优先级为 50）

### 示例 3：创建列表问答卡片

```markdown
【 item 
- FSRS 的优点
  - 科学的间隔算法
  - 自适应学习曲线
  - 开源免费
】
```

**自动操作**：
- 2 秒后自动检测
- 识别为 Item（列表项有列表子级）
- 添加到 Riff Deck
- 标记 `custom-fsrs-card-type: item`

## 验证方法

### 方法 1：查看控制台日志

1. 按 `F12` 打开开发者工具
2. 切换到"控制台"选项卡
3. 创建新卡片后，等待 2 秒
4. 查看日志输出：

```
[FSRS] WS Event: transactions
[FSRS] Transaction received: 1
[FSRS] Ops: insert <blockId>
[FSRS] Processing queue, blocks: 1
[FSRS] Topic card created: blockID=<blockId>, aFactor=3.6
```

### 方法 2：查看卡片浏览器

1. 打开卡片浏览器（左键点击顶栏 FSRS 图标）
2. 找到新创建的卡片
3. 查看 CardType 列，应该显示 `Topic` 或 `Item`（不再是 `-`）

### 方法 3：查看块属性

1. 右键点击卡片块
2. 选择"属性"
3. 查看自定义属性：
   - `custom-fsrs-card-type`: `topic` 或 `item`
   - `custom-fsrs-a-factor`: A-Factor 值（仅 Topic）

## 常见问题

### Q1: 为什么新卡片没有被自动检测？

**可能原因**：
1. 自动制卡功能未启用（检查设置）
2. 防抖延迟（等待 2 秒）
3. 块内容不符合制卡规则（检查策略匹配）

**解决方法**：
1. 确认设置中已启用"自动制卡（实时监听）"
2. 等待 2 秒后再检查
3. 查看控制台日志，确认是否有错误

### Q2: 为什么 CardType 显示 `-`？

**可能原因**：
1. 卡片是在启用自动制卡之前创建的
2. 自动检测失败（查看控制台错误）

**解决方法**：
1. 手动触发识别：打开浏览器 → 点击"识别 Topic/Item 类型"按钮
2. 或者重新编辑卡片内容，触发自动检测

### Q3: 可以修改已有卡片的类型吗？

**可以**，有两种方法：

**方法 1：手动全量识别**
1. 打开卡片浏览器
2. 点击工具栏"识别 Topic/Item 类型"按钮
3. 确认后会重新识别所有卡片

**方法 2：编辑触发（需启用自动制卡）**
1. 编辑卡片内容
2. 等待 2 秒
3. 自动重新检测类型

### Q4: 自动制卡会影响性能吗？

**不会**，原因：
1. 使用 2 秒防抖，避免频繁触发
2. 批量处理，每批 10 个卡片
3. 只在启用时才监听事件
4. 错误处理完善，不会阻塞主流程

### Q5: 可以调整防抖延迟时间吗？

**目前不可以**，防抖延迟固定为 2 秒。

如果需要调整，可以修改代码：

```typescript
// src/core/box/TransactionObserver.ts
this.debounceTimer = setTimeout(() => {
  this.processQueue();
}, 2000); // ← 修改这里的延迟时间（毫秒）
```

## 其他触发方式

除了自动触发，还有以下触发方式：

### 1. 手动触发（浏览器按钮）

- 打开卡片浏览器
- 点击工具栏"识别 Topic/Item 类型"按钮
- 确认后全量识别所有卡片

**适用场景**：
- 批量识别现有卡片
- 重新识别所有卡片
- 修复识别错误

### 2. 启动触发

- 插件启动后 2 秒自动检查
- 如果发现未标记的卡片，显示确认对话框
- 确认后自动识别

**适用场景**：
- 首次使用插件
- 升级插件后
- 导入新卡片后

## 技术细节

### 监听的事件

- WebSocket 事件：`ws-main`
- 操作类型：`insert`（插入）、`update`（更新）

### 检测流程

```
用户创建/编辑块
    ↓
WebSocket 事件
    ↓
添加到待处理队列
    ↓
防抖 2 秒
    ↓
批量处理
    ↓
1. 获取块内容
2. 匹配制卡策略
3. 检查现有状态
4. 同步到 Riff Deck
5. 检测卡片类型
6. 初始化 A-Factor（Topic）
7. 保存到存储
```

### A-Factor 计算

Topic 卡片的 A-Factor 从优先级推导：

```
aFactor = 1.2 + (priority / 100) * 4.8
```

- 优先级 0 → A-Factor 1.2
- 优先级 50 → A-Factor 3.6
- 优先级 100 → A-Factor 6.0
