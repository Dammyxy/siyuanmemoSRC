# 手动测试指南：评分 1-2 卡片旋转修复

## 测试目标

验证评分 1-2 的卡片不会立即再次出现，而是会让其他到期卡片先出现。

## 测试前准备

### 1. 确认插件已构建并安装

插件已构建到：`H:/SiYuanXY/data/plugins/siyuan-plugin-fsrs`

### 2. 重启思源笔记

确保加载最新版本的插件。

### 3. 准备测试卡片

创建至少 **3-5 张闪卡**，确保它们都是"到期"状态：

**方法 A：使用已有的到期卡片**
- 在"提取练习"队列中，应该已经有一些到期的卡片
- 确保至少有 3 张卡片

**方法 B：创建新卡片并设置为到期**
1. 创建 3-5 个新的闪卡块
2. 将它们添加到 Riff 卡包
3. 等待它们变为"到期"状态（或手动修改数据库）

## 测试步骤

### 测试场景 1：基本旋转测试

1. **打开提取练习队列**
   - 点击插件图标
   - 选择"提取练习"模式
   - 确认队列中有至少 3 张卡片

2. **记录初始状态**
   - 记下第一张卡片的 ID 或内容（称为 Card-A）
   - 记下队列中的总卡片数

3. **评分第一张卡片为 1 或 2**
   - 对 Card-A 评分为 **1**（完全忘记）或 **2**（部分记得）
   - 观察下一张卡片

4. **验证结果**
   - ✅ **期望行为**：下一张卡片应该是 Card-B（不是 Card-A）
   - ❌ **Bug 行为**：下一张卡片又是 Card-A（立即重复）

5. **继续复习**
   - 继续复习队列中的其他卡片
   - 观察 Card-A 何时再次出现
   - ✅ **期望**：Card-A 应该在其他卡片之后出现

### 测试场景 2：连续失败测试

1. **对第一张卡片评分 1 或 2**
2. **对第二张卡片也评分 1 或 2**
3. **对第三张卡片也评分 1 或 2**

4. **验证结果**
   - ✅ **期望**：三张失败的卡片应该按某种顺序重新出现
   - ✅ **期望**：不应该连续看到同一张卡片两次
   - ❌ **Bug**：某张卡片立即重复出现

### 测试场景 3：混合评分测试

1. **对第一张卡片评分 1 或 2**（失败）
2. **对第二张卡片评分 3 或 4**（成功，应该从队列移除）
3. **对第三张卡片评分 1 或 2**（失败）

4. **验证结果**
   - ✅ **期望**：评分 3-4 的卡片不再出现
   - ✅ **期望**：评分 1-2 的卡片会重新出现，但不会立即重复
   - 队列大小应该减少（评分 3-4 的卡片被移除）

### 预期日志模式

1. 失败卡片的 `nextDues` 被设置为当前时间（不是过去时间）

1. 失败卡片的 `dueTime` 比所有其他卡片都早

3. 用户连续看到同一张卡片

## 已知限制

### 1. Outstanding 队列模式

提取练习队列使用 **Outstanding 模式**，只显示 `dueTime <= now` 的卡片。

**影响**：
- 如果队列中只有 1 张到期卡片，评分 1-2 后，它仍然会立即出现（因为没有其他到期卡片）
- 这是**正常行为**，不是 bug

**解决方法**：
- 确保测试时队列中有多张到期卡片

### 2. 时间精度

修复依赖于毫秒级的时间差异。

**影响**：
- 在极少数情况下，如果两张卡片的 `dueTime` 完全相同，排序可能不稳定
- 这不影响实际使用，因为用户评分之间通常有几秒钟的间隔

## 故障排查

### 问题 1：失败卡片仍然立即重复

**可能原因**：
1. 队列中只有 1 张到期卡片
2. 插件没有重新加载（使用了旧版本）
3. 浏览器缓存问题

**解决方法**：
1. 确保队列中有多张到期卡片
2. 重启思源笔记
3. 清除浏览器缓存（Ctrl+Shift+Delete）

### 问题 2：控制台没有日志

**可能原因**：
1. 开发者工具没有打开
2. 日志级别设置过高

**解决方法**：
1. 按 F12 打开开发者工具
2. 切换到 Console 标签
3. 确保日志级别设置为 "All" 或 "Verbose"

### 问题 3：队列为空

**可能原因**：
1. 没有到期的卡片
2. Riff 卡包为空

**解决方法**：
1. 创建新的闪卡并添加到 Riff
2. 等待卡片到期，或手动修改数据库
