## 第一阶段：紧急修复 (Phase 1)

### 1.1 观察者模式实现

**问题**: 手动调用 reset() 导致缓存不一致，容易遗漏。

**解决方案**:
- 实现 `IObservableDataSource` 和 `IDataSourceObserver` 接口
- DataSource 修改数据时自动通知所有观察者
- Sequencer 收到通知后自动失效缓存

**成果**:
- ✅ 消除所有手动 reset() 调用
- ✅ 缓存自动同步，避免数据不一致
- ✅ 降低组件耦合度

**代码示例**:
```typescript
// 数据源自动通知
class RiffDataSource extends ObservableDataSource<ReviewCard> {
  async remove(items: ReviewCard[]): Promise<Result<number>> {
    const result = await this.doRemove(items);
    if (result.ok) {
      this.notifyObservers(); // 自动通知
    }
    return result;
  }
}

// Sequencer 自动失效
class PrioritySequencer implements IDataSourceObserver {
  onDataChanged(): void {
    this.loaded = false; // 自动失效
  }
}
```

**参考**: `docs/adr/ADR-002-observer-pattern.md`

### 1.6 错误恢复机制

**问题**: 数据库错误导致系统崩溃，用户体验差。

**解决方案**:
- 实现三层降级策略
- 添加用户友好的错误消息
- 实现错误报告系统

**成果**:
- ✅ 数据库失败时使用缓存
- ✅ 用户收到清晰的错误提示
- ✅ 错误自动报告到监控系统

**降级策略**:
```typescript
async fetchAll(): Promise<TItem[]> {
  try {
    // 第一层：正常查询
    return await this.queryDatabase();
  } catch (error) {
    // 第二层：使用缓存
    if (this.cachedCards.length > 0) {
      showNotice('使用缓存数据（数据库暂时不可用）');
      return this.cachedCards;
    }
    // 第三层：返回空数组并报告
    this.errorReporter.report(error);
    showNotice('加载卡片失败，请稍后重试');
    return [];
  }
}
```
