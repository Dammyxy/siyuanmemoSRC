# DDD 架构重构 - 需求文档

## 1. 概述

### 1.1 目标

将 siyuan-plugin-siyuanmemo 从传统插件架构重构为 DDD（领域驱动设计）架构，降低代码复杂度，提升可维护性，为后续统一 xiuyuan 系统打下基础。

### 1.2 背景

当前 index.ts 文件有 1448 行代码，违反单一职责原则，包含了插件入口、服务初始化、UI 管理、事件处理和业务逻辑等多种职责。这导致：
- 代码难以理解和维护
- 测试困难
- 新功能开发受阻
- 技术债务累积

### 1.3 范围

本次重构采用渐进式方案，分 4 个阶段实施：
1. 创建应用上下文（ApplicationContext）
2. 重构 Xiuyuan 为 DDD 模型
3. 创建应用服务层
4. 迁移现有功能

## 2. 用户故事

### 2.1 作为开发者，我希望代码结构清晰

**用户故事**：
作为插件开发者，我希望代码按照清晰的分层架构组织，这样我可以快速定位和修改代码。

**验收标准**：
- index.ts 文件少于 200 行
- 代码按照表现层、应用层、领域层、基础设施层组织
- 每个文件职责单一，易于理解

### 2.2 作为开发者，我希望业务逻辑可测试

**用户故事**：
作为插件开发者，我希望核心业务逻辑可以独立测试，不依赖思源笔记环境。

**验收标准**：
- 领域模型可以单元测试
- 应用服务可以单元测试
- 单元测试覆盖率 > 80%

### 2.3 作为开发者，我希望依赖关系清晰

**用户故事**：
作为插件开发者，我希望模块之间的依赖关系清晰，避免循环依赖。

**验收标准**：
- 使用依赖注入
- 依赖方向从外向内（表现层 → 应用层 → 领域层）
- 没有循环依赖

### 2.4 作为用户，我希望所有功能正常工作

**用户故事**：
作为插件用户，我希望重构后所有功能继续正常工作，不影响我的使用。

**验收标准**：
- 所有现有功能正常工作
- 数据不丢失
- 性能不下降
- 用户体验不变

## 3. 功能需求

### 3.1 应用上下文（ApplicationContext）

**需求描述**：
创建统一的应用上下文，管理所有服务的生命周期和依赖注入。

**验收标准**：
- [ ] 3.1.1 ApplicationContext 可以创建和销毁
- [ ] 3.1.2 可以通过 ApplicationContext 获取所有服务
- [ ] 3.1.3 服务之间的依赖自动注入
- [ ] 3.1.4 支持懒加载
- [ ] 3.1.5 有完整的单元测试

### 3.2 Xiuyuan 领域模型

**需求描述**：
将 Xiuyuan 重构为 DDD 聚合根，封装业务规则。

**验收标准**：
- [ ] 3.2.1 Xiuyuan 聚合根可以创建、更新、删除
- [ ] 3.2.2 业务规则在领域模型中验证
- [ ] 3.2.3 使用值对象（XiuyuanId, CardFace 等）
- [ ] 3.2.4 发布领域事件
- [ ] 3.2.5 单元测试覆盖率 > 80%

### 3.3 仓储模式（Repository）

**需求描述**：
创建仓储接口和实现，统一数据访问层。

**验收标准**：
- [ ] 3.3.1 定义 IXiuyuanRepository 接口
- [ ] 3.3.2 实现 XiuyuanRepository
- [ ] 3.3.3 协调 msgpack、块属性、Riff 三个数据源
- [ ] 3.3.4 领域模型与持久化模型转换
- [ ] 3.3.5 集成测试通过

### 3.4 应用服务层

**需求描述**：
创建应用服务和用例，封装业务逻辑。

**验收标准**：
- [ ] 3.4.1 创建 CreateCardUseCase
- [ ] 3.4.2 创建 DeleteCardUseCase
- [ ] 3.4.3 创建 UpdateCardUseCase
- [ ] 3.4.4 创建 CardApplicationService
- [ ] 3.4.5 用例可以独立测试

### 3.5 UI 管理器

**需求描述**：
从 index.ts 提取 UI 管理逻辑到专门的管理器。

**验收标准**：
- [ ] 3.5.1 创建 DialogManager
- [ ] 3.5.2 创建 MenuManager
- [ ] 3.5.3 创建 TabManager
- [ ] 3.5.4 所有 Dialog 可以正常打开
- [ ] 3.5.5 所有 Menu 可以正常显示
- [ ] 3.5.6 所有 Tab 可以正常工作

### 3.6 简化 index.ts

**需求描述**：
将 index.ts 简化为薄薄的入口层。

**验收标准**：
- [ ] 3.6.1 index.ts 少于 200 行
- [ ] 3.6.2 只负责插件生命周期管理
- [ ] 3.6.3 只负责 UI 事件路由
- [ ] 3.6.4 所有业务逻辑移到应用层
- [ ] 3.6.5 插件可以正常加载和卸载

## 5. 约束条件

### 5.1 技术约束

- 必须使用 TypeScript
- 必须兼容现有的 Vue 3 UI 组件
- 必须兼容思源笔记插件 API
- 必须使用 Vitest 作为测试框架

### 5.2 时间约束

- Phase 1: 2-3 小时
- Phase 2: 3-4 小时
- Phase 3: 2-3 小时
- Phase 4: 1-2 小时
- 总计: 8-12 小时

### 5.3 风险约束

- 必须采用渐进式重构，新旧代码可共存
- 每个 Phase 完成后必须进行手动测试
- 发现问题可以随时回滚
