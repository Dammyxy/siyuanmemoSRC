# DDD 重构 - 测试指南

## 测试概览

本指南将帮助你验证 DDD 重构后的功能是否正常工作。测试分为三个部分：
1. 单元测试和集成测试（自动化）
2. 插件加载/卸载测试（手动）
3. 功能测试（手动）

---

## 1. 自动化测试

### 1.1 运行核心单元测试

这些测试验证 DDD 架构的核心组件：

```bash
# 领域层测试
npm test -- --run src/core/xiuyuan/domain/__tests__/

# 应用层测试
npm test -- --run src/application/usecases/
npm test -- --run src/application/services/

# 基础设施层测试
npm test -- --run src/core/xiuyuan/infrastructure/
```

**预期结果**：所有测试应该通过（绿色 ✓）

### 1.2 运行集成测试

```bash
# ApplicationContext 集成测试
npm test -- --run src/application/__tests__/ApplicationContext.di.test.ts
npm test -- --run src/application/__tests__/dependency-injection.integration.test.ts
npm test -- --run src/application/__tests__/service-access.integration.test.ts

# CardApplicationService 集成测试
npm test -- --run src/application/services/__tests__/CardApplicationService.integration.test.ts
```

**预期结果**：所有测试应该通过

**注意**：如果测试失败并显示 "Failed to parse URL from /api/file/putFile"，这是正常的测试环境问题，不影响实际功能。

## 2. 插件加载/卸载测试

### 2.1 构建插件

```bash
cd siyuan-plugin-siyuanmemo
npm run build
```

### 2.2 测试插件加载

1. 将构建好的插件复制到思源笔记的插件目录
2. 重启思源笔记或刷新插件列表
3. 启用 "SiYuan Memo" 插件

**验证点**：
- [ ] 插件成功加载，没有错误提示
- [ ] 顶部工具栏出现 SiYuan Memo 图标
- [ ] 控制台输出：`[SiYuanMemo] Plugin loaded successfully`
- [ ] 控制台输出：`[ApplicationContext] ✅ ApplicationContext created successfully`

### 2.3 测试插件卸载

1. 在思源笔记中禁用插件
2. 检查控制台输出

**验证点**：
- [ ] 插件成功卸载，没有错误
- [ ] 顶部工具栏的图标消失
- [ ] 控制台没有错误信息

### 2.4 测试插件重新加载

1. 重新启用插件
2. 验证所有功能正常

**验证点**：
- [ ] 插件重新加载成功
- [ ] 之前的数据仍然存在
- [ ] 所有功能正常工作

## 3. 功能测试

### 3.1 卡片创建测试

#### 测试场景 1：通过块菜单创建模板卡片

1. 在思源笔记中创建一个测试文档
2. 写入一些内容块（建议至少 2 个块）
3. 选中这些块，右键点击块图标
4. 在菜单中找到 "创建模板卡片" 选项
5. 在弹出的对话框中选择模板（如 "基础问答"）
6. 点击确认

**验证点**：
- [ ] 菜单中显示 "创建模板卡片" 选项
- [ ] 对话框正常弹出
- [ ] 可以选择不同的模板
- [ ] 显示选中的块数量
- [ ] 显示模板的字段和卡片生成规则
- [ ] 卡片创建成功，显示成功提示
- [ ] 控制台输出：`[DialogManager] Xiuyuan created`

#### 测试场景 2：创建不同类型的模板卡片

测试所有内置模板：
- [ ] 基础问答（Basic Q&A）
- [ ] 填空题（Cloze）
- [ ] 双向卡片（Bidirectional）
- [ ] 多选题（Multiple Choice）

**验证点**：
- [ ] 每种模板都能成功创建卡片
- [ ] 卡片数据正确保存
- [ ] 生成的卡片数量符合模板规则

#### 测试场景 3：通过思源原生快速制卡

1. 在思源笔记中创建一个测试文档
2. 写入一些内容块
3. 右键点击块图标 → 选择思源原生的 "制作闪卡" 选项

**验证点**：
- [ ] 思源原生制卡功能正常工作
- [ ] 卡片被正确添加到 Riff 系统

#### 测试场景 4：创建列表模版卡

1. 在思源笔记中创建一个包含有序列表的块
2. 右键点击父块图标 → 选择 "创建列表模版卡"
3. 确认创建

**验证点**：
- [ ] 只有包含有序列表的块才能使用此功能
- [ ] 为每个列表项创建一张卡片
- [ ] 显示创建成功的卡片数量

### 3.2 卡片删除测试

#### 测试场景 1：通过块菜单删除卡片

1. 找到一个已创建卡片的块
2. 右键点击块图标 → 选择 "取消闪卡"
3. 确认删除

**验证点**：
- [ ] 删除选项正常显示
- [ ] 卡片删除成功，显示成功提示
- [ ] 控制台输出：`[CardApplicationService] Card deleted successfully`

#### 测试场景 2：通过浏览器删除卡片

1. 点击顶部工具栏的 SiYuan Memo 图标
2. 在卡片浏览器中找到一张卡片
3. 点击删除按钮
4. 确认删除

**验证点**：
- [ ] 浏览器正常打开
- [ ] 删除按钮可用
- [ ] 卡片从列表中消失

### 3.3 卡片更新测试

#### 测试场景：修改卡片内容

1. 找到一个已创建卡片的块
2. 修改块的内容
3. 保存

**验证点**：
- [ ] 卡片内容自动更新
- [ ] 修改后的内容在复习时正确显示

### 3.4 卡片复习测试

#### 测试场景 1：开始复习

1. 点击顶部工具栏的 SiYuan Memo 图标
2. 点击 "开始复习" 按钮
3. 进行复习

**验证点**：
- [ ] 复习界面正常打开
- [ ] 卡片内容正确显示
- [ ] 可以进行评分（Again, Hard, Good, Easy）

#### 测试场景 2：复习评分

1. 在复习界面中
2. 依次测试所有评分按钮
3. 观察卡片的下次复习时间

**验证点**：
- [ ] 所有评分按钮都能正常工作
- [ ] 评分后卡片状态更新
- [ ] 下次复习时间合理

### 3.5 卡片浏览器测试

#### 测试场景：浏览和筛选卡片

1. 点击顶部工具栏的 SiYuan Memo 图标
2. 在浏览器中测试各种功能

**验证点**：
- [ ] 卡片列表正确显示
- [ ] 可以按状态筛选（新卡片、学习中、复习中）
- [ ] 可以搜索卡片
- [ ] 卡片统计信息正确

### 3.6 设置测试

#### 测试场景：打开和修改设置

1. 右键点击顶部工具栏的 SiYuan Memo 图标
2. 选择 "设置"
3. 修改一些设置
4. 保存

**验证点**：
- [ ] 设置对话框正常打开
- [ ] 可以修改各种设置
- [ ] 设置保存成功
- [ ] 重新加载插件后设置仍然保留

## 4. 性能测试

1. 禁用插件
2. 清空浏览器控制台
3. 启用插件
4. 记录从开始到 "Plugin loaded successfully" 的时间

2. 记录从点击确认到成功提示的时间

1. 在复习界面中

**预期结果**：响应时间应该在 500ms 以内

## 9. 快速测试脚本

如果你想快速验证核心功能，可以按照以下顺序测试：

1. **构建并加载插件**（2 分钟）
2. **创建一张卡片**（1 分钟）
3. **复习这张卡片**（1 分钟）
4. **删除这张卡片**（1 分钟）
5. **卸载并重新加载插件**（1 分钟）

总计：约 6 分钟

如果这 5 个步骤都通过，说明核心功能正常，可以进行更详细的测试。

## 10. 常见问题

### Q: 测试时遇到 "Failed to parse URL" 错误怎么办？
A: 这是测试环境的问题，不影响实际功能。在真实的思源笔记环境中不会出现这个问题。

### Q: 插件加载后没有看到图标怎么办？
A: 检查控制台是否有错误信息，确保插件构建成功。

### Q: 卡片创建后找不到怎么办？
A: 打开卡片浏览器，检查卡片是否在列表中。如果不在，检查控制台错误。

### Q: 如何查看详细的日志？
A: 打开浏览器开发者工具（F12），查看 Console 标签页。
