# 队列架构说明

## 旧架构（Old Architecture）
- 目录：`src/core/queue/strategies/`
- 状态：已物理移除，不再参与运行时路径
- 迁移遗留：仅保留在诊断报告历史记录中

## 新架构（New Architecture）
- 队列目录：`src/core/queue/domain/`
- 应用入口：`src/application/services/UnifiedDataSourceManager.ts`
- 队列接口：`IReviewQueue`（`src/types/unified-data-source.ts`）
- 适配层：`UnifiedQueueStrategy`（`src/application/adapters/UnifiedQueueStrategy.ts`）
- 已注册队列：RetrievalPractice, IncrementalLearning, FilterGroup, FinalDrill, NeuralRoam, Leech

## 类型差异（QueueItem vs FSRSCard）
- `QueueItem`：更轻量，适用于旧队列策略，字段不全且松散
- `FSRSCard`：字段完整，包含调度信息、状态与扩展元数据

## 迁移指南
1. 所有新行为统一落在 `core/queue/domain` + `UnifiedDataSourceManager` 主链路
2. 禁止新增旧策略目录或并行队列实现
3. UI 通过 DialogManager/ReviewAdapter 访问队列，避免跨层直接依赖
4. 使用 `queue.getAllCards()` 获取卡片列表
5. 跑通单元与集成测试再删除旧代码
