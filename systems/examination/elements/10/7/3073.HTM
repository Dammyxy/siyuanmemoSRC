  1. 核心数据模型 (Morpheme) ankimorphs 的基石是 Morpheme 类。它不仅仅是一个简单的单词，而是包含了语言学上的重要信息：

    • lemma（词元）：词典中的基本形式，如 "break"。
    • inflection（词形变化）：单词在句子中出现的具体形式，如 "broke", "broken"。
    • part_of_speech（词性）：如名词、动词等。
    • highest_..._learning_interval（最高学习间隔）：这个属性是关键，它记录了包含该 lemma 或 inflection 的卡片中，最长的复习间隔。这个数值直接决定了该语素的掌握状态（STATUS_UNKNOWN, STATUS_LEARNING, STATUS_KNOWN）。

  2. 数据库设计 (AnkiMorphsDB) 插件通过一个独立的 SQLite 数据库 ankimorphs.db 来管理和追踪学习数据，这与 Anki 自身的数据库是分开的。其核心是一个多对多的关系模型：

    • Cards 表：缓存 Anki 卡片的基本信息。
    • Morphs 表：存储所有遇到过的语素（Morpheme）及其学习间隔。
    • Card_Morph_Map 表：这是一个关联表，它将 Cards 和 Morphs 连接起来，清晰地记录了“哪个卡片包含哪些语素”。
    • Seen_Morphs 表：一个临时表，用于追踪当天已经复习过的语素，以优化某些功能的性能。

    这种设计使得 ankimorphs 能够独立于 Anki 的数据结构，进行高效的查询和计算，例如：

    • 快速查找包含特定语素的所有卡片。
    • 计算每个语素的“已知”状态。
    • 生成学习进度报告。

  3. 语素分析器 (Morphemizers) 从文件结构和代码中的 import 语句（例如 spacy_wrapper, mecab_wrapper, jieba_wrapper）可以看出，ankimorphs 的设计是模块化的，它支持多种不同的自然语言处理工具（如 SpaCy, MeCab, Jieba）来对文本进行分词和语素分析。这意味着用户可以根据自己学习的语言（如日语、中文、英语等）选择最合适的分词引擎。这是一个非常灵活和可扩展的设计。

我将从 recalc_main.py 文件入手，因为它很可能是 recalc 功能的主入口。同时，为了理解计算的具体逻辑，我将一并阅读 card_morphs_metrics.py 和 card_score.py，这两个文件从命名上看，似乎与卡片语素的度量和评分直接相关。

在深入分析了 recalc 模块的三个核心文件后，我对 ankimorphs 如何量化和更新学习进度有了清晰的认识。这个过程可以概括为以下几个步骤：

1. 触发与准备 (recalc_main.py)

  • 入口函数: recalc() 是所有重新计算操作的起点。它被设计为一个后台任务（QueryOp），以防止在处理大量卡片时 Anki 主界面冻结。
  • 缓存数据 (caching.cache_anki_data): 这是 recalc 的第一步，也是非常关键的一步。它会遍历用户在设置中指定的所有 Anki 卡片，从中提取文本，使用对应的语素分析器（Morphemizer）进行分词，然后将卡片、语素及其学习间隔（interval）等信息全部缓存到 ankimorphs.db 数据库中。这一步构建了后续所有计算所需的数据基础。
  • 优先级确定 (morph_priority_utils.get_morph_priority): 在计算卡片分数之前，系统会确定每个语素的“优先级”。这个优先级可以基于语素在整个卡片集合中的出现频率（默认方式），也可以基于用户提供的外部优先级文件。出现频率越高的语素，其优先级数值越低（即越重要）。

2. 卡片度量 (card_morphs_metrics.py)

  • 在对每张卡片进行评分之前，CardMorphsMetrics 类会先对卡片上的语素进行一次全面的“体检”，计算出一系列核心指标：

    • all_morphs: 卡片上所有的语素列表。
    • unknown_morphs: 卡片上完全未知的语素列表（即 learning_interval == 0）。
    • num_learning_morphs: 处于“学习中”状态的语素数量。
    • total_priority_* 和 avg_priority_*: 基于上一步计算出的语素优先级，统计出卡片上所有/未知/学习中语素的总优先级和平均优先级。

    这些度量指标为接下来的卡片评分提供了所有必要的输入数据。

3. 卡片评分与排序 (card_score.py)

  • 这是 recalc 模块的“大脑”。CardScore 类实现了一个复杂的评分算法，为每一张新卡片（CARD_TYPE_NEW）计算一个分数（score），这个分数直接决定了卡片在学习队列中的顺序。
  • 核心评分公式:
    <TEXT>
    score = (未知语素数量 * 巨大惩罚值) + 微调项
    • 巨大惩罚值 (MORPH_UNKNOWN_PENALTY): 这是一个非常大的常数（1,000,000）。这意味着，一张卡片上每多一个未知语素，它的分数就会增加一百万。这确保了包含 0 个未知语素的卡片（i+0）永远排在包含 1 个未知语素的卡片（i+1）之前，包含 1 个未知语素的卡片永远排在包含 2 个未知语素的卡片之前，以此类推。这是实现“i+1”理论的核心机制。
    • 微调项 (tuning): 当两张卡片具有相同数量的未知语素时，微调项就开始发挥作用。它是一个由多个加权参数（如语素优先级、目标语素数量差异等）组成的综合值。通过调整这些参数的权重，用户可以根据个人偏好对学习顺序进行微调，例如，是优先学习包含高频词的卡片，还是优先学习包含接近目标词汇量卡片。
  • 最终排序: 计算出的 score 会被赋值给卡片的 due 字段。Anki 会根据 due 值的大小来排序新卡片，due 值越小的卡片排在越前面。

总结 recalc 模块的设计思路非常精妙。它首先通过一个巨大的惩罚值，严格执行了“i+1”的学习原则，确保用户总是在学习只包含一个生词的材料。然后，在这个基本原则之上，它提供了一套灵活的“微调”系统，允许用户根据词频、词汇密度等多种因素，精细地调整学习路径。整个过程高效、自动化，并且高度可配置。

通过对 highlighting 模块的分析，我清晰地了解了 ankimorphs 是如何实现“即时”（Just-In-Time）生词高亮的。这个过程同样设计得非常巧妙和高效。

1. 触发点 (highlight_just_in_time.py)

  • Anki 模板过滤器: ankimorphs 在 Anki 中注册了一个自定义的模板过滤器，例如 {{am-highlight:FieldName}}。当 Anki 渲染卡片、遇到这个过滤器时，就会调用 highlight_morphs_jit 函数。这是整个高亮流程的入口。

2. 即时分析 (_get_morph_meta_for_text)

  • 与 recalc 的不同: 与 recalc 模块在后台对整个牌组进行批量分析不同，高亮模块是在卡片显示时才对当前字段的文本进行“即时”分析。
  • 文本清洗: 首先，它会调用 _dehtml 函数，这个函数非常关键。它不仅会移除标准的 HTML 标签，还会特别处理 Anki 的振假名（furigana）语法（如 漢字[かんじ] 或 <ruby><rb>漢字</rb><rt>かんじ</rt></ruby>），将其统一转换回 ankimorphs 内部能够识别的格式。
  • 调用语素分析器: 清洗后的文本被传递给当前笔记类型配置的 Morphemizer，进行实时分词。
  • 查询数据库: 得到语素列表后，函数会立即查询 ankimorphs.db 数据库，获取每个语素的 highest_learning_interval，从而确定其当前的掌握状态（Known, Learning, Unknown）。

3. 文本高亮 (text_highlighter.py)

  • TextHighlighter 类是实现高亮的核心。它的工作可以分为两个阶段：
    • 信息收集 (__init__):
      1. _tag_rubies: 首先，它会从文本中找出所有的振假名（ruby）标记，并记录下它们的位置和内容。
      2. _tag_morphemes: 接着，它会在不包含振假名标记的纯文本上，从长到短匹配上一步分析出的语素，并记录下每个语素的位置和学习状态（Status 对象）。
    • 合并处理 (_process): 这是最复杂的部分。该方法从后往前同时处理 rubies 和 statuses 这两个队列。它通过比较语素和振假名的位置关系（如完全重合、部分重叠、无交集等），智能地决定如何将它们合并，并用 <span> 标签包裹起来。例如：
      • 如果一个语素和一个振假名完全重合，它会将振假名（<ruby>...）包裹在带有学习状态的 <span> 标签内，如：<span morph-status="unknown"><ruby>...</span>。
      • 如果语素分析器出错了（例如，将一个完整的单词拆成了多个语素），导致语素和振假名无法完美对应，它会优先相信用户手动添加的振假名，并将该部分标记为 STATUS_UNDEFINED，避免显示错误的颜色。

4. 样式定义 (status_class.py, ruby_classes.py)

  • Status 类负责生成最终的 HTML <span> 标签，它会添加一个 morph-status 属性（如 morph-status="known"）。
  • Ruby 系列的类则负责根据不同的高亮模式（如仅显示汉字、仅显示假名、或显示完整的振假名）生成对应的 HTML <ruby> 结构。
  • 最终，用户需要在 Anki 卡片模板的 CSS 部分为这些 morph-status（unknown, learning, known）定义具体的颜色、背景等样式，从而在视觉上区分生词和熟词。

总结 highlighting 模块的设计充分体现了“延迟计算”和“关注点分离”的原则。它不在 recalc 阶段生成和存储高亮后的 HTML，而是等到卡片真正需要显示时才进行即时分析和渲染。这大大降低了 recalc 的复杂度和数据库的存储压力。同时，通过 TextHighlighter 类对语素状态和振假名样式的复杂合并逻辑进行封装，使得代码结构清晰，易于维护。

AnkiMorphs 整体设计思路总结

AnkiMorphs 作为一个强大的 Anki 语言学习插件，其设计的核心是以“语素”（Morpheme）为最小学习单位，通过量化追踪用户对每个语素的掌握程度，最终实现对新卡片学习顺序的智能排序，以达到最高效的“i+1”学习路径。

整个系统可以看作一个围绕 ankimorphs.db 数据库运转的数据处理流水线：

  1. 数据采集与缓存 (caching): 这是所有分析的基础。插件首先从 Anki 的卡片集合中批量提取文本，利用可插拔的语素分析器 (Morphemizer) 将文本分解为 Morpheme 对象，然后将卡片与语素的对应关系、以及每个语素的学习状态（基于卡片复习间隔 interval）缓存到自己的独立数据库 ankimorphs.db 中。

  2. 学习进度量化 (recalc): 这是插件的“大脑”。它基于数据库中的缓存数据，通过一个精心设计的评分算法 (CardScore) 为每一张新卡片打分。该算法的核心是对包含未知语素的卡片施加巨大惩罚，从而在宏观上严格保证了“i+0, i+1, i+2...”的学习顺序。在此基础上，它还引入了词频、词汇密度等多种“微调”参数，让具有相同未知词数量的卡片之间也能有更科学的排序。

  3. 实时反馈 (highlighting): 这是插件与用户交互最直接的部分。它并非在 recalc 阶段预先生成高亮文本，而是在 Anki 渲染卡片的瞬间，对当前卡片上的文本进行即时（Just-In-Time） 的语素分析和数据库查询，然后动态地为不同掌握程度（未知、学习中、已知）的语素包裹上相应的 CSS 类，最终在界面上呈现出彩色的高亮效果。

架构优势

  • 解耦与独立性 (Decoupling & Independence): 通过建立独立的 ankimorphs.db 数据库，ankimorphs 将自己的核心数据和计算逻辑与 Anki 自身复杂的数据结构解离开来。这样做的好处是巨大的：

    • 性能提升: 针对性的数据库设计和索引使得语素相关的查询非常高效。
    • 易于维护: 无需深入了解 Anki 数据库的内部细节，插件自身的逻辑更清晰、更内聚。
    • 稳定性: Anki 数据库结构的未来变化对 ankimorphs 核心功能的影响降到最低。

  • 模块化与可扩展性 (Modularity & Extensibility): 插件的语素分析功能被设计成一个可插拔的 Morphemizer 接口。这意味着：

    • 可以轻松地为新的语言（如中文、俄语等）添加支持，只需实现一个新的 Morphemizer 子类（如 JiebaMorphemizer）。
    • 用户可以根据自己的需求和语言特点，选择最适合的自然语言处理引擎（SpaCy, MeCab 等）。

  • 性能考量 (Performance Consideration): 设计者在多个方面都对性能进行了优化：

    • 后台处理: 将耗时最长的 recalc 操作放在后台线程执行，避免了 Anki 界面的卡顿。
    • 即时计算: 将高亮操作放在卡片渲染时进行，避免了在 recalc 阶段对海量卡片进行不必要的文本处理和存储，节省了大量时间和空间。
    • 缓存机制: 大量使用缓存（如 lru_cache），减少了重复的计算和数据库查询。

  • 用户体验与可配置性 (UX & Configurability): 插件在严格遵循核心算法的同时，也提供了丰富的配置选项，让用户可以根据自己的学习习惯进行深度定制。例如，CardScore 算法中的各个权重参数、是否将“全认识”的卡片移到队尾等，都赋予了用户极大的灵活性。

综上所述，ankimorphs 是一个在软件工程和语言学习理论两方面都堪称典范的项目。它通过清晰的架构、模块化的设计和对性能的极致追求，成功地将复杂的“i+1”学习理论转化为一个自动化、高效且用户友好的工具。
